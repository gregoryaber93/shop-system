### 3) **Praktyczny workflow w VS Code + Copilot Chat**

#### **A) Przed przystąpieniem do kodu**
1. **Przeczytaj odpowiednie instrukcje** — jeśli piszesz feature: `01-architecture` + `07-delivery-devx`.
2. **Ustal kontekst** — screen/komponenty dotyczy jaki serwis (Products, Auth, Orders)?
3. **Sprawdź FEATURE-SEQUENCE** — czy feature jest planowany, w jakim sprincie?

#### **B) Pisanie promptu do Copilota** (pattern)
```
Kontekst:
- Piszę [eksport] w [moduł].
- Integracja z [serwis API] (backend: [endpoint]).
- Zależności: [inne komponenty/hooksy].

Cel:
- Po tej zmianie [konkretne zachowanie].
- User powinien widzieć [co na ekranie].

Ograniczenia:
- Użyj TypeScript strict + Zod do walidacji.
- Separation of concerns: API client → hooks → komponenty.
- States: loading → error → empty → success.
- Testy: behavior tests (user interaction, nie implementation details).

Wyjście spodziewane:
- Kod + testy + lista ryzyk.
```

#### **C) Proces wdrażania**
1. **Przeczytaj instrukcje** mogące się odnosić (np. #02 dla API client).
2. **Skopiuj wzory** z instrukcji (np. kod `AuthContext` z #08).
3. **Dostosuj do sprawy** — nazwy, schematy, endpointy.
4. **Uruchom linter + typecheck** — musi przejść, brak `any`.
5. **Napisz testy** — co najmniej happy path + jeden error case.
6. **Otaguj PR** — link do instrukcji, opis ryzyko.

#### **D) Szybka referencja w Copilot**
Zamiast całą instrukcję czytać, pisz query:
- `"Show me pattern for React Query hook from instruction 09"`
- `"How do I handle 401 in error interceptor?"`
- `"Example MSW handler for products mocking"`

### **Podsumowanie: "Golden Rules"**

1. **Zawsze separuj**: API client ≠ Component ≠ Hook.
2. **Typy pierwszy**: Zod + TypeScript strict, zero `any`.
3. **States zawsze**: loading → error → empty → success.
4. **Testy obowiązek**: behavior, nie implementation, MSW mock.
5. **Prompt = sukces**: Daj kontekst + cel + ograniczenia, Copilot robi resztę.
6. **PR male**: jedan feature = jeden PR, opis = ryzyk + rollback.
7. **Query keys stabilne**: Nie duplikuj, referencja + namespacing.
8. **Error mapping**: Backend ProblemDetails → user message w UI.
9. **Performance**: Bundle < 300KB, lazy routes, React Query defaults.
10. **gRPC reality**: Timeout 10s, may fail gracefully, UNAVAILABLE = 503.
